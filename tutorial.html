1. Symbolic route

  1. Open Symbolic Lab.
  2. Select Logistic growth or Lotka–Volterra.
  3. Edit one RHS expression and press Analyze.
  4. Use the numeric sliders / scope to set parameters and initial conditions.
  5. Try these plot modes: expression curve, phase-line, time course, vector field, nullcline scan and parameter sweep.
  6. Export SymPy for exact solving or publication-grade validation.

2. Agent route

  1. Open the Agent Model Atlas for scenario context, then open Agent Lab.
  2. Select T-cell, SIR, fatty-acid de novo, vaccine hesitancy, meme-stock, forest fire or Game of Life.
  3. Read the Rule definition before interpreting the grid.
  4. Choose the modeling approach, time update and topology. Change named parameters A–D and compare population, composition, phase and event plots.
  5. Switch to custom local rule executed in the Agent Lab Web Worker sandbox or apply a custom model JSON, edit the rule body, apply it, then step once before running.
  6. Export JSON to preserve the rule, parameters and seed.

3. Workbench route

  1. Open Model Atlas and choose a model.
  2. Change one parameter first. Run the simplest plot.
  3. Move to landscape, sensitivity, ECDF or parallel coordinates only when they answer a concrete question.
  4. For your own lightweight ODE or 2D optimization model, use the custom JSON import panel.

4. Stochastic route

Run multiple stochastic simulations before interpreting anything. One Gillespie, Monte Carlo π or noisy Fibonacci run is a sample path, not the expectation.

5. Research route

Use Research Hub for portfolio evidence. Source-derived figures carry scientific meaning; generated diagrams are secondary summaries only.

6. All labs custom model route

  1. Start by choosing the lab that matches the model class.
  2. Use the visible method or modeling approach selector before running.
  3. For Agent Lab, use the dropdowns for Rule-Based Decision Making, State-Driven / Statecharts, Adaptive & Learning Agents, Graph / Network-Based Approach with random, small-world or multilayer spatial/social/transport contacts, and Continuous vs. Discrete Time. Keep long explanations in the Model Atlas.
  4. Paste or edit the custom model JSON, then run a one-step diagnostic before long runs.
  5. Export JSON/Python/SymPy for reproducibility and external validation.

7. Failure checks

  • Button seems inactive: check the status line. Errors should be visible there.
  • Symbolic plot blank: check variable names, numeric scope, plot mode and ranges.
  • Agent result unclear: switch plot mode first. Read the Model Atlas or the collapsed rule table only when you need the model logic.
  • Custom rule fails: return a valid state index for the selected model; slow or invalid custom code is rejected or terminated by the worker timeout or an object such as {state, trait, event}; avoid browser-blocking loops.
  • Scientific claim too strong: export and validate externally.
