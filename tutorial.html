Foko Lab tutorial

Complete practical walkthrough

This tutorial is compact but dense. It is designed to fit well as a PDF without empty pages. Each section gives the action, the expected result, and the failure check.

Common workflow

  1. Choose a model.
  2. Inspect the mathematical form.
  3. Edit parameters or equations.
  4. Run / solve / optimize.
  5. Inspect plots and diagnostics.
  6. Export reproducible files.

Page layout

All labs follow the ODE Lab mental model: left workflow rail, middle editor, right plotting workspace. This reduces switching cost between deterministic, algebraic, stochastic and optimization problems.

1. Start with the Model Atlas

Action

Open Model Atlas. Use the top filters first by lab class: ODE, Optimization, Steady State, or Stochastic. Then narrow by domain such as Biology, Physics, Chemistry, Paradoxes, Teaching, Simulation, or Foko Models.

Expected result

Each card opens the correct lab with a URL like ode.html?example=Lorenz, steady.html?example=Toggle%20switch, or stochastic.html?example=birth-death.

2. ODE Lab: deterministic dynamics

Run Lorenz

  1. Open ODE Lab.
  2. Load Lorenz.
  3. Press Run.
  4. Switch plots between trajectory, 2D phase, 3D phase, vector field, and Poincaré section.

Expected result

The right workspace shows two visible Plotly figures. The metrics row reports steps, evaluations, CPU time, and tolerance. 3D plots should not leave a stale “Run to plot” placeholder.

Numerical warning: browser RK methods are exploratory. If the model is stiff or biologically high-stakes, export to Python and validate with Radau, BDF, or LSODA.

3. ODE Lab: parameter sweep

Action

Switch to Parametric ODE, choose sweep parameters, pick an output variable and metric, then press Sweep.

Expected result

The workspace shows a heatmap or contour-like response surface. Use this for qualitative sensitivity, not formal uncertainty quantification.

Sweep fieldMeaning
Param A / Param BTwo varied parameters.
OutputState variable to summarize.
MetricFinal, mean, max or min value over the simulated trajectory.
Grid sizeNumber of parameter values per axis. Higher grid sizes cost more.

4. Steady-State syntax: paste equations safely

The Steady-State Lab solves expressions as f(x,p)=0. One equation corresponds to one variable. The parser accepts rough pasted text but always inspect the parsed preview before solving.

Messy paste

C:quadkonES−koffC−kcatC=0,
x:quadax−bxy=0,
y:quaddxy−cy=0

Parsed meaning

C: kon*E*S - koff*C - kcat*C = 0
x: a*x - b*x*y = 0
y: d*x*y - c*y = 0
Check: the math preview must not display raw \[4pt], quad, or unexpanded implicit products such as konES.

5. Steady-State solve and interpretation

Action

  1. Choose Toggle switch bistability or SIR endemic equilibrium.
  2. Inspect parsed equations.
  3. Press Solve.
  4. Open diagnostics if the residual is not small.

Expected result

The equilibrium plot appears on the left, the residual history appears on the right, and the diagnostics report residual norm, iteration count, and local Jacobian classification.

Interpretation: local Jacobian classification is only dynamical stability if the algebraic system is interpreted as dx/dt = f(x,p). For pure algebraic constraints, convergence means residual convergence, not stability.

6. Steady-State continuation

Action

Choose a parameter such as alpha, beta, or lambda. Set min, max and number of points. Press λ Continuation.

Expected result

The left plot shows a branch curve; the right plot shows residual quality. If the plot is empty, run Solve first and check that the chosen parameter exists.

Limitation: this is simple warm-start continuation. It can miss folds, switch branches, or show only one stable branch of a bistable system.

7. Stochastic Lab: CTMC / Gillespie ensembles

Action

  1. Open Stochastic Lab.
  2. Choose Birth-death or Stochastic SIR.
  3. Set runs, seed, time horizon and grid points.
  4. Press Run ensemble.

Expected result

The two ODE-style plot panels update. The left panel can show paths, mean trajectory, or mean-field overlay. The right panel can show distribution, diagnostics, or event heatmap.

SettingRecommended first valueRisk if too large
runs100–300Large memory and slower rendering.
max events5,000–50,000Truncation before final time.
grid points200–800Large arrays and slower export.

8. Stochastic mean-field overlay

Use case

Enable Mean-field overlay when you want to compare stochastic averages with the deterministic approximation implied by propensities.

Warning

Mean-field may fail for small copy numbers, extinction-dominated systems, highly nonlinear propensities, or systems with absorbing states.

Correctness rule: CTMC events that would produce negative state counts are blocked before firing. If many events are blocked, inspect the propensity and update rules.

9. Optimization Lab: convex problems and landscapes

Action

  1. Choose Convex bowl or Constrained quadratic.
  2. Set a seed.
  3. Press Optimize.
  4. Use Landscape / contours for the left plot.

Expected result

For two-variable convex examples, a contour or heatmap-like objective landscape should always be available. The best candidate is marked on top of the objective surface.

Trust rule: browser optimization is approximate. Validate scientific or engineering conclusions externally with SciPy, CasADi, Pyomo, JuMP, or another production solver.

11. Exports and reproducibility

Data exports

  • Wide CSV: spreadsheet inspection.
  • Long CSV: tidy data for R/Python.
  • Plotly JSON: figure recreation.
  • Model JSON: exact editable state.

Code exports

Python and Julia exports are reproducibility scaffolds, not a guarantee that browser results are production-grade. Use external solvers for validation.
