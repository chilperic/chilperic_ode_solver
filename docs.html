Focused Labs: scope and depth roadmap

The integrated Workbench is the broad route. Focused Labs are the direct single-paradigm workspaces: ODE + Parametric ODE, Stochastic CTMC, Optimization, and Steady-State. They expose direct single-paradigm controls that would overload a general workbench: deterministic sweeps, CTMC event editing, optimization setup and algebraic continuation.

ODE Lab

  • Current strength: deterministic solver, parametric ODE workflow, phase/trajectory diagnostics and exports.
  • Required depth: events/discontinuities, time-varying inputs, experimental-data overlay, fitting bridge, IC sweeps and uncertainty bands.

Stochastic Lab

  • Current strength: CTMC/Gillespie event model with editable states, propensities and ensemble exports.
  • Required depth: seeded reproducibility, tau-leaping, Euler-Maruyama SDEs, quantile ribbons, extinction probabilities and deterministic comparison.

Optimization Lab

  • Current strength: direct objective setup, starts, bounds, samples and convergence diagnostics.
  • Required depth: gradient, Newton, simplex/interior-point, genetic algorithm, simulated annealing, particle swarm, constraints and Pareto front diagnostics.

Steady-State Lab

  • Current strength: algebraic equations, Newton solve, residual check, Jacobian stability and continuation.
  • Required depth: two-parameter continuation, Hopf/fold classification, root basins, nullclines and profile-based validation.

Core workflow

  1. Choose ODE, stochastic CTMC, optimization, steady-state, symbolic, agent or SciML.
  2. Load a curated model or import your own JSON.
  3. Edit initial conditions, parameter values, ranges, solver/setup values and the diagnostic target.
  4. Run one baseline case.
  5. Add only plots that answer a modeling question.
  6. Export JSON, CSV, Python, SymPy/SciPy or figures for validation outside the browser.

ODE Lab

Use ODE models for continuous deterministic dynamics. A strong workflow includes solver choice, stiffness awareness, event handling, phase portraits, vector fields, parameter sweeps, sensitivity analysis and calibration against data.

Optimization Lab

Use optimization models for objectives, constraints and trade-offs. The Workbench exposes initial guesses, bounds, parameter values, method families, population/starts, tolerance and seed. Use gradient-based methods for smooth problems and metaheuristics for rugged or multimodal landscapes.

Steady-State Lab

Use steady-state models for algebraic balances, roots, equilibria, residual checks, local Jacobian stability, continuation and sensitivity. A converged residual is not automatically a scientific validation.

Stochastic Lab

Use CTMC and Gillespie-style models when event timing and random trajectories matter. Always inspect ensemble paths, final distributions, extinction probabilities, run count, seed and deterministic comparison.

Symbolic Lab

Use symbolic computation for exact differentiation, simplification under assumptions, Jacobians, Taylor expansions, equation inspection and code generation. Rendered mathematics is the primary output; raw LaTeX should not be the user-facing result.

Agent Lab

Use ABM for decentralized systems with heterogeneous local rules, spatial grids, contact networks and emergent behavior. Validate through repeated runs, summary statistics, calibration and ODD-style documentation.

SciML Lab

SciML bridges mechanistic models and data-driven learning: inverse problems, surrogate modeling, SINDy, PINN/UDE export scaffolds, residual plots, loss curves, train/validation splits and uncertainty-aware diagnostics.

Scientific limits

Browser execution is for exploration and teaching. Use exported local scripts for stiff systems, large ABMs, large CTMC ensembles, publication-quality inference, uncertainty quantification and HPC workflows.

Custom models

Custom models can be imported through JSON in the Workbench. Current browser authoring is strongest for ODE and 2D optimization; CTMC, steady-state, symbolic and agent models have dedicated pages and export routes while the full Workbench authoring contract is consolidated.

Agent execution limits

Custom Agent Lab rules run in agent-rule-worker.js with a worker timeout. Multilayer spatial/social/transport contacts are supported for browser-scale tests, but large ABM studies should be exported or reproduced externally.

Plot standard

Put plot controls directly above the graph, keep variables selectable, and do not treat a decorative plot as evidence. Use the simplest diagnostic that can reject the current model assumption.

What every model should expose

Inputs

State variables, population size, initial conditions, parameter values, bounds, solver/setup, seed and time horizon.

Diagnostics

Trajectory, phase portrait, residual, convergence, sensitivity, sweep, uncertainty, feasibility and validation plots.

Export

JSON for reproducibility, CSV for results, Python/SciPy/SymPy/PyTorch scaffolds for serious local computation.

SciML export boundary

Browser SciML is for inverse-problem, SINDy, surrogate and small-data ML diagnostics. Heavy PINNs, UDEs, GPU training, probabilistic UQ and large neural networks should be exported to Python/PyTorch/JAX workflows.

Audit · What is possible

Browser-native scope for the unified analysis stack

Possible now

  • Statistics, regression, hypothesis tests and moderate plotting.
  • Linear algebra for small/medium dense matrices and geometric intuition.
  • ML baselines: clustering, PCA, binary/linear models, anomaly screening.
  • Networks: connectivity, shortest paths, PageRank and adjacency views.

Possible with a heavier browser engine

  • Pyodide/Wasm-backed scientific Python for expanded stats and scikit-learn.
  • ONNX Runtime Web or TensorFlow.js for lightweight inference.
  • Web Workers and IndexedDB for asynchronous compute and local persistence.

Not realistic without external compute

  • Deep learning training, LLM fine-tuning, large graph analytics and GPU orchestration.
  • Huge datasets, enterprise lineage, graph databases and model registries.
  • Anything requiring stable server-side storage or collaboration backends.

Steady-State scientific upgrade

2-parameter continuation and bifurcation classification

The Steady-State Lab now supports one-parameter continuation with branch-level stability classification and a two-parameter continuation map. Use it to inspect equilibrium branches, residual reliability, candidate fold points, Hopf-like crossings in 2D Jacobian systems, and regions where Newton solves do not converge.

Recommended plots

Continuation branch, continuation residual, Jacobian heatmap, Hopf/fold markers, bifurcation class counts and 2D continuation heatmap.

Scientific caution

Hopf/fold labels are numerical candidates from finite-difference Jacobians and continuation sign changes. Treat them as screening diagnostics, then validate in exported Python or a dedicated bifurcation package.

V71.19 reproducibility

Session, share URL and bundle export/import

Every lab now receives compact reproducibility controls: save the current session, restore it, copy a shareable URL, export a full JSON bundle and import that bundle later. The bundle stores the page, release, form state, visible outputs and timestamp so a model run can be archived with a project or paper draft.

Use it during exploration

Save session after a working setup, copy the share URL before sharing a configuration, and export a bundle when the result should be preserved outside the browser.

What is included

Input fields, selected modes, pasted datasets, parameter values, output text, page identity, release version and browser URL state.

What is not included

Large binary files, external Python results, server-side collaboration history and publication-grade provenance beyond the browser session.

V71.21 compute bus

Shared worker execution

Long browser computations now have one platform execution path for progress, cancellation and crash cleanup. ODE, Parametric ODE and Optimization use the bus-compatible worker handle first; other labs can be migrated without changing their scientific engines.

Analysis labs: plottable examples and diagnostics

The Statistics, Curve Fitting, Linear Algebra and Network labs now start from concrete scientific examples. Each example loads data or a matrix/edge list, runs immediately and renders two plots: a primary result plot and a secondary diagnostic.

  • Statistics: A/B testing, housing regression, sensor noise, survival, credit risk, RSM yield, churn, air quality, quality control and gene-expression FDR.
  • Curve fitting: enzyme kinetics, logistic growth, decay, rheology, PK/PD, spectral peaks, thermal calibration, adsorption, battery discharge and wave packets.
  • Linear algebra: PageRank, SVD compression, least squares, quantum eigenstates, truss systems, Markov chains, stoichiometric null spaces, PCA, graphics transforms and diffusion matrices.
  • Networks: electrical grids, supply chains, epidemic transmission, call graphs, financial contagion, telecom routing, corporate flows, citation trees, metabolic pathways and traffic networks.
