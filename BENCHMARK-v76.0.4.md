# Foko Lab platform benchmark

This benchmark guides product design; it does **not** claim numerical or feature parity
with mature desktop, server, or commercial scientific platforms.

| Reference platform | Useful design lesson for Foko Lab |
| --- | --- |
| VCell | Keep equations, geometry, simulations, parameters, and results attached to one model project. |
| SimBiology | Make model construction primary and compatible tasks—simulation, fitting, sensitivity, and design—secondary. |
| COPASI | Expose numerical method, status, diagnostics, and reproducible reports alongside results. |
| Tellurium | Preserve a low-friction route from an editable mathematical model to a scriptable reproducible experiment. |
| Cell Collective | Use strong visual model interaction where structure and network behavior benefit from it. |
| BioUML | Treat analysis methods as interoperable project operations, not disconnected demonstrations. |
| Simulink | Keep model, experiment settings, run controls, diagnostics, and comparison views in one workspace. |
| COMSOL | Organize complex work as model tree → study → results, with contextual visualization. |

## Benchmark dimensions

- **Scientific reliability:** finite-input validation, solver evidence, seeded stochastic
  methods, explicit capability boundaries, independent references, and stale-result safety.
- **Platform stability:** one application shell, deterministic release gates, plot lifecycle
  ownership, bounded browser budgets, and recoverable project import/export.
- **UX:** project-first entry, task compatibility, compact controls, user-owned models,
  strong examples as optional templates, and direct creator/trust access.
- **Modern GUI:** a restrained scientific palette, clear type scale, portal navigation,
  responsive phone sheet and bottom controls, accessible focus, and contextual 3D.

Foko Lab’s differentiator is a browser-native modeling workspace that combines editable
mechanistic, population, agent, data-driven, Bayesian, optimization, and sensitivity
workflows with explicit evidence boundaries. The Model Atlas supports the workflow but
does not define the product.
