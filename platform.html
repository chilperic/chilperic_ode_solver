Platform architecture

Foko Lab operating model

A modeling platform is not a pile of calculators. It needs a shared grammar: define a scientific question, formalize the model or dataset, run a validated engine, inspect diagnostics, and export the reproducible state when the browser is no longer enough.

Model registryData engineCompute enginesDiagnosticsExport boundary

Current design rule

Every lab must expose controlsInitial conditions, parameters, method, plot mode and export state.
Every engine must be testablePure Node-exported numeric core plus browser UI wrapper.
Every result must be diagnosedNot just a number: residuals, uncertainty, stability, validation or topology.

Modeling engines

  • ODE, stochastic, optimization, steady-state, symbolic and agent-based workflows.
  • Controls should include parameters, initial conditions, solver/method and plot mode.
  • Export to Python/JSON when browser execution is no longer sufficient.

Data / Analysis engines

  • Statistics, fitting, linear algebra and network analysis share the same project controls.
  • Inputs can be pasted or imported locally into the first editor.
  • Outputs must include model diagnostics, not only summary values.

SciML / ML boundary

  • Browser-native ML is for small-data diagnostics and educational baselines.
  • Heavy ML, deep learning, LLM tuning and GPU training belong outside the browser.
  • Future upgrade path: Pyodide, Web Workers, ONNX Runtime Web and IndexedDB.

Capability parity audit

Workbench: model setup → run → plots → export
Statistics: data → tests/regression → diagnostic plots → macro
Fitting: observations → model family → residuals/AIC/BIC → export
Linear Algebra: matrix/vector → operation → geometry/decomposition → export
Networks: edge list → graph algorithm → topology visualization → export
ML Toolkit: feature table → learner → validation diagnostics → export

Known hard limitations

No shared persistent project database yet.
No Web Worker compute isolation for every engine yet.
No Pyodide/SciPy/scikit-learn runtime yet.
No large graph rendering engine yet.
No collaborative model registry yet.
These are architectural upgrades, not cosmetic fixes.

Export boundary

Exported scripts

When browser execution is no longer appropriate, Foko Lab workflows should move into exported scripts, JSON project states, Python notebooks or larger external compute environments.

V71 platform foundation

What V71 changes structurally

Reproducibility

  • Local session save/load.
  • Shareable URL state.
  • Run-bundle JSON export.
  • Seeded randomness through FokoKit.

Scientific substrate

  • Curated JSON model registry.
  • Nonlinear fitting helper with confidence intervals.
  • Tau-leaping and Euler-Maruyama helper cores.
  • Basin map and continuation helper cores.

Platform UX

  • Command palette: press /.
  • Plot export buttons.
  • Upload/schema validation helpers.
  • Shared guard and result-formatting vocabulary.

V71.21 compute bus

Shared worker execution

Long browser computations now have one platform execution path for progress, cancellation and crash cleanup. ODE, Parametric ODE and Optimization use the bus-compatible worker handle first; other labs can be migrated without changing their scientific engines.
