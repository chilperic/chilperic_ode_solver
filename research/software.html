Scientific problem / Engineering problem

How do you let users explore models interactively without pretending that a browser replaces publication-grade Python, CasADi, SALib, or full experimental pipelines?

The platform separates three layers: teaching examples, safe reduced surrogates, and research narratives. That separation is the important architectural decision. It protects unpublished work while still demonstrating that you can build usable scientific tools.

What this sells

The platform itself is evidence that I can design scientific software around real modeling constraints: model routing, safe exports, protected unpublished work, reproducible local tests, and user-facing documentation. Visual regression testing remains the next hardening step, because static tests cannot catch all layout failures. A mature platform must include browser click-through, screenshot comparison, and guarded release commands that do not start the server when tests fail.

Scientifically, the platform demonstrates that I understand the difference between a teaching solver, a reduced surrogate, and a publication-grade research pipeline. That distinction matters for trust: a browser can communicate mechanisms, but calibrated work still belongs in Python/R repositories with tests, data provenance and explicit limitations.

Implementation discipline

For portfolio use, this platform should show that I do not only write equations or produce figures. I also package scientific models into tools that another person can inspect, run and criticize. That means clean routing, explicit project boundaries, local tests, JavaScript syntax checks, link audits, protected unpublished pages, and documentation that explains what each model is allowed to claim. The strongest engineering message is not that everything runs in the browser; it is that the browser interface is honest about its scope and points to reproducible computational workflows when deeper analysis is required.

Limitations

  • Browser models cannot replace calibrated research pipelines.
  • Visual regression testing is still needed for a mature release.
  • Some legacy CSS remains dense and should eventually be consolidated.
  • Export boundaries must remain strict for unpublished plant work.
