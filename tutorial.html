Focused Lab workflows

Use Focused Labs when the scientific question is already specific: deterministic dynamics, stochastic events, optimization setup or algebraic equilibria. Detailed scope and missing depth are documented in Focused Labs documentation.

ODE + Parametric ODE

Start from a deterministic model, then sweep one or two parameters to see phase, trajectory and metric sensitivity. Next scientific upgrade: event handling, data overlay, fitting bridge and uncertainty bands.

Stochastic CTMC

Define states and events explicitly, run ensembles, and compare individual paths to summary distributions. Next scientific upgrade: seeded reproducibility, tau-leaping, Euler-Maruyama and extinction statistics.

Optimization

State objective, bounds and initial guesses directly, then inspect candidate traces and convergence. Next scientific upgrade: method families, constraints, Pareto diagnostics and multi-start comparison.

Steady-State

Write algebraic equations, solve roots, inspect residuals and continue parameters. Next scientific upgrade: two-parameter continuation, Hopf/fold classification and basins of roots.

Upload templates by lab

These are minimal structures that a user can copy, modify, save as JSON/CSV/TXT, and upload or paste into the relevant lab. The goal is not decoration; each template exposes the model question, editable assumptions, and first diagnostic.

ODE Lab · JSON model

Use for deterministic continuous-time systems.

{
  "type": "ode",
  "name": "custom_sir",
  "vars": ["S", "I", "R"],
  "params": {"beta": 0.45, "gamma": 0.12, "N": 1000},
  "init": {"S": 990, "I": 10, "R": 0},
  "ranges": {"beta": [0, 2], "gamma": [0, 1]},
  "eqs": [
    "dS/dt = -beta*S*I/N",
    "dI/dt = beta*S*I/N - gamma*I",
    "dR/dt = gamma*I"
  ],
  "tspan": [0, 160],
  "diagnostic": "trajectory"
}

Stochastic Lab · CTMC events

Use when finite population noise matters.

{
  "type": "ctmc",
  "name": "stochastic_sir",
  "states": {"S": 990, "I": 10, "R": 0},
  "params": {"beta": 0.45, "gamma": 0.12, "N": 1000},
  "events": [
    {"name": "infection", "rate": "beta*S*I/N", "change": {"S": -1, "I": 1}},
    {"name": "recovery", "rate": "gamma*I", "change": {"I": -1, "R": 1}}
  ],
  "runs": 100,
  "seed": 42,
  "diagnostic": "sample_paths_and_ensemble"
}

Optimization Lab · objective and bounds

Use for parameter search, control, fitting, or design.

{
  "type": "optimization",
  "name": "bounded_quadratic",
  "variables": {"x": 1.2, "y": -2.0},
  "bounds": {"x": [-6, 6], "y": [-6, 6]},
  "objective": "(x-1)^2 + (y+2)^2",
  "constraints": ["x + y <= 3"],
  "method": "projected_gradient",
  "iterations": 180,
  "tolerance": 1e-7,
  "diagnostic": "landscape_and_convergence"
}

Steady-State Lab · residual equations

Use for equilibria, balances and continuation.

{
  "type": "steady_state",
  "name": "enzyme_balance",
  "unknowns": {"x": 0.5, "y": 0.2},
  "params": {"k1": 2.0, "k2": 0.7},
  "residuals": ["k1*(1-x)-k2*x*y", "x-y"],
  "continuation": {"parameter": "k1", "min": 0.2, "max": 5, "steps": 80},

}

Export to Python for real deep learning, PINNs, UDEs or GPU training.

1. Equation model

  1. Open Workbench → ODE.
  2. Select SIR, Lotka–Volterra or Van der Pol.
  3. Edit initial conditions and at least one parameter range.
  4. Run a trajectory.
  5. Add phase portrait and sensitivity only after the baseline is plausible.
  6. Export Python for stiff or publication-grade solving.

2. Calibrate an optimization problem

  1. Open Workbench → Optimization.
  2. Select a problem and open Advanced simulation settings.
  3. Set x/y initial guess, bounds, method, population/starts and tolerance.
  4. Change one parameter value and one parameter range.
  5. Run, then inspect convergence, landscape, feasibility and Pareto/frontier plots.

3. Analyze a steady state

  1. Choose a steady-state model.
  2. Edit the initial guess and continuation parameter range.
  3. Solve once.
  4. Check residual, Jacobian classification and alternative equilibria.
  5. Run continuation before claiming stability.

4. Run a stochastic model

  1. Choose a CTMC model.
  2. Set population size, seed and number of runs.
  3. Compare ensemble mean, sample paths and final distribution.
  4. Repeat under a parameter change; one stochastic run is not evidence.

5. Symbolic route

  1. Choose or type an expression/system.
  2. Render the expression first.
  3. Compute derivative, Jacobian, simplification or assumptions-based result.
  4. Only then request a numeric plot.
  5. Export SymPy when exact reproducibility matters.

6. Agent route

  1. Select an agent example.
  2. Set population/grid size and update rule settings; custom rules must return a valid state index for the selected model.
  3. Run repeated simulations.
  4. Compare spatial view, counts, network/contact diagnostics and summary statistics.
  5. Document the model using ODD-like assumptions.

7. Workbench route and SciML

  1. Select inverse problem, surrogate or SINDy.
  2. Set train/validation split, noise, candidate parameters and bounds.
  3. Inspect loss curves, predicted-vs-reference, residual distributions and extrapolation behavior.
  4. Export PyTorch/Python for heavy PINN, UDE or GPU workflows.

Failure checks

  • Plot looks smooth: that does not prove correctness.
  • Optimization converged: check constraints and starting-point dependence.
  • Stochastic run worked: inspect ensemble statistics.
  • Symbolic plot blank: check numeric scope and ranges. Symbolic output exists: verify assumptions and variable names.
  • Agent result unclear: inspect rules and plot modes. worker timeout: reduce grid size or rule complexity. Browser is slow: reduce budget or export locally.

Data / Analysis standard

Examples and plot coverage for analysis labs

Each analysis lab exposes plottable examples: choosing an example loads real input data and renders an immediate diagnostic plot. The plot menu then lets the user inspect the same example through alternative views.

Statistics

Examples: growth regression, A/B proportions, ANOVA groups, SPC signal, correlation matrix, bootstrap CI, outlier screen, multiple regression.

Plots: scatter, line, bar, histogram/KDE, box, violin, heatmap, bubble, SPLOM, Pareto, residual, Q-Q and ECDF.

Curve fitting

Examples: exponential growth, enzyme saturation, logistic saturation, residual stress, exact linear, dose response, decay-like data, cubic calibration.

Plots: fit overlay, fit band, residual, Q-Q, predicted-vs-observed, residual histogram, parameter bars, cumulative residual and influence proxy.

Linear algebra

Examples: solve Ax=b, eigenpair, least squares, Markov transition, projection, linear transform, PCA data cloud, null-space case.

Plots: matrix heatmap, vector arrows, transformation grid, eigenvector lines, projection vector, least-squares line, Markov diagram, PCA score plot and condition/spectrum bars.

Networks

Examples: social graph, weighted transport, Sankey flow, community graph, centrality hub, resilience, bipartite interaction, directed PageRank matrix.

Plots: circular graph, force-style graph, adjacency heatmap, Sankey, degree distribution, centrality bars, shortest-path highlight, community layout and resilience curve.

Focused Lab workflow

Steady-State: continuation workflow

  1. Open Steady-State and load a nonlinear model such as Toggle switch, Brusselator, Logistic carrying capacity or Lake phosphorus.
  2. Solve the baseline equilibrium and inspect residual plus Jacobian classification.
  3. Choose a continuation parameter, range and point count; run continuation.
  4. Use Hopf/fold markers and class-count plots to locate candidate transitions.
  5. Choose a second parameter and run the 2-parameter continuation map only after the 1D branch looks numerically reliable.
  6. Export JSON/Python for confirmation outside the browser.

V71.19 reproducibility

Session, share URL and bundle export/import

Every lab now receives compact reproducibility controls: save the current session, restore it, copy a shareable URL, export a full JSON bundle and import that bundle later. The bundle stores the page, release, form state, visible outputs and timestamp so a model run can be archived with a project or paper draft.

Use it during exploration

Save session after a working setup, copy the share URL before sharing a configuration, and export a bundle when the result should be preserved outside the browser.

What is included

Input fields, selected modes, pasted datasets, parameter values, output text, page identity, release version and browser URL state.

What is not included

Large binary files, external Python results, server-side collaboration history and publication-grade provenance beyond the browser session.

V71.21 compute bus

Shared worker execution

Long browser computations now have one platform execution path for progress, cancellation and crash cleanup. ODE, Parametric ODE and Optimization use the bus-compatible worker handle first; other labs can be migrated without changing their scientific engines.

Analysis labs: plottable examples and diagnostics

The Statistics, Curve Fitting, Linear Algebra and Network labs now start from concrete scientific examples. Each example loads data or a matrix/edge list, runs immediately and renders two plots: a primary result plot and a secondary diagnostic.

  • Statistics: A/B testing, housing regression, sensor noise, survival, credit risk, RSM yield, churn, air quality, quality control and gene-expression FDR.
  • Curve fitting: enzyme kinetics, logistic growth, decay, rheology, PK/PD, spectral peaks, thermal calibration, adsorption, battery discharge and wave packets.
  • Linear algebra: PageRank, SVD compression, least squares, quantum eigenstates, truss systems, Markov chains, stoichiometric null spaces, PCA, graphics transforms and diffusion matrices.
  • Networks: electrical grids, supply chains, epidemic transmission, call graphs, financial contagion, telecom routing, corporate flows, citation trees, metabolic pathways and traffic networks.
